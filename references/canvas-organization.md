# Figma 画布整理

目标是让交付可浏览、可交接、无散落和重叠；不把画布排版升级为产品规范。

## 1. 分区（`Section`）

- 建立或复用一个主交付 Section，按业务名和交付范围命名。
- 收纳必要说明、业务 Frame 和真实缺口组件。
- 只有组件自身固定视觉导致画布对比不足时，才建立独立组件 Section；不得为适配画布改组件内部视觉。
- Section 与业务内容保持可读对比，但 Section 不设置会被后代继承的产品主题 mode。

## 2. 分区内容

按需要排列：

1. 真实缺口组件；
2. 本轮新增说明；
3. 按任务流和状态排序的业务 Frame。

间距和行列根据节点实际尺寸计算；不压缩业务 Frame，不硬编码某次项目的列数或坐标。

## 3. 命名

- Section：业务名｜交付范围
- 业务 Frame：序号 + 页面/状态；必须是 Frame，不是 Group
- 缺口组件：`AI-新增/语义名`
- 实例、布局、surface、内容、图标、图片、分隔、说明按职责命名
- 临时节点使用 `tmp/*`，交付前必须为 0

远程实例内部名称保持源组件原样。

## 4. 整理步骤

1. 收集本轮节点，清除测试节点、隐藏素材、重复外置标题和临时节点。
2. 移入交付 Section。
3. 按任务流和状态排列，使用实际包围盒计算位置。
4. 根据内容更新 Section 边界。
5. 截完整 Section 和主要状态，检查顺序、对比和可读性。

## 5. 审计

- 无意外交叠、越界、文本裁切或异常固定高度；
- overlay 之外没有自由散落的业务节点；
- 交付节点全部在 Section 内；
- 无默认图层名、重复标题或 `tmp/*`；
- Section 没有改变业务 Frame 的主题和变量；
- 业务屏根节点是 Frame，不是 Group；
- layout-only 无默认视觉；surface 角色明确；
- 缺口组件没有为画布展示而改内部规范。
