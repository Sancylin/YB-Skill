# 典型交互模式

以下布局/视觉模式仅在现场团队规范可追溯且场景命中时作为 team-rule；无依据时为可解释调整的 heuristic，不以本文措辞独立阻断。工具限制、实例身份保护和需求覆盖仍为硬性不变量。规则分类见 [采集与验证契约](capture-and-validation.md)。
全产品共用这一份清单。生成前冻结、生成后验收、已有稿评审和独立复评都必须读完整份，不准只读目录就停。

先用当前任务的页面和状态去对每条 `when`。只把命中的 `patternId` 写入状态矩阵和验收；未命中的不要套用。装配规则仍按 [design-guidelines.md](design-guidelines.md)，不要把本文件当成布局配方。组件名、Variant、key 不写在这里，选型走现场 description。

以后典型特例往本文件追加，不新开分支。

## 目录

| patternId | when 摘要 |
|---|---|
| `form-validation-timing` | 信息收集表单：未完成置灰禁用，错误统一走 Toast，不顶开布局 |
| `in-stream-weak-network` | 对话生成中弱网：保持输出中，延迟轻提示 |
| `page-weak-network` | 落地页弱网：整页说明和恢复 |
| `page-empty` | 落地页空状态：整页说明，无主内容可展示 |
| `rounded-group-caption-inset` | 圆角表单/列表旁的标题或底注：左对齐但内收 |
| `edge-chrome-vs-content-inset` | 同一屏既有贴边壳层又有内容卡片：壳层铺满画布，内容才用页面边距 |
| `system-ime-keyboard` | 系统输入法已升起：用正式 Keyboard 贴底铺满，不手绘、不用图标代替 |

落地页级空、错、弱网缺省共用一条对齐：插画 + 说明 + 恢复相对**整机画板**上下居中。顶栏、状态栏仍保留，但不从居中参考框里扣除。禁止把缺省内容放进「顶栏下方剩余列」再在该列内垂直居中——视觉会明显偏下。缺省层可铺满画板并居中，顶栏叠在上层；不要改成内容柱先排顶栏、再在剩余空间里垂直居中。

## 条目

### `in-stream-weak-network`

```text
patternId: in-stream-weak-network
when: 对话或生成式回答还在输出时网络变差
surfaceLevel: in-stream
stay: 保持正在输出或思考中，不切完成态
after: 过几秒用非阻断轻提示告知弱网
never: 整页空态；输出完成后改成落地页缺省；用页面级恢复代替流内进行中
```

### `page-weak-network`

```text
patternId: page-weak-network
when: 搜索或操作后进入的落地页本身弱网或该页请求失败
surfaceLevel: page
stay: 整页说明当前无法展示，并在有恢复路径时给出恢复
layout: 缺省内容相对整机画板垂直居中；顶栏不计入居中参考框的上边界
after: 无额外延迟提示要求；恢复后回到该页内容
never: 套进生成式回答流；用正在输出中冒充落地页弱网；在顶栏下方剩余列里垂直居中
```

### `page-empty`

```text
patternId: page-empty
when: 进入落地页后主列表或主内容为空（无结果、未创建、已清空），需要整页说明而不是列表里的一行提示
surfaceLevel: page
stay: 整页说明当前没有内容，有主操作时给出下一步
layout: 与落地页弱网相同，缺省内容相对整机画板垂直居中
after: 有内容后回到该页列表或详情
never: 画成对话流空态；把空说明塞进列表第一行冒充整页空；在顶栏下方剩余列里垂直居中
```

### `rounded-group-caption-inset`

```text
patternId: rounded-group-caption-inset
when: 圆角表单或圆角列表组旁边还有左对齐标题，或底部还有辅助说明；不是对话 Markdown 正文
stay: 标题/说明仍左对齐；左右留白让文字对上圆角容器的内边内容，而不是外框切角
never: 标题或底注与圆角外框左缘齐平显得更探出；把这条套到 Markdown 正文流
```

### `edge-chrome-vs-content-inset`

```text
patternId: edge-chrome-vs-content-inset
when: 同一屏里既有贴设备左右边缘的壳层（顶栏、长按条、锁定操作条、系统键盘、Tab、全宽底栏），又有需要离开屏幕边缘的内容（流式文本框、卡片、列表、表单）
stay: 壳层铺满当前设备画布，与画布或同屏已铺满的条对齐；页面边距只作用在内容层，用独立 inset 包装或 Hug/Fixed 居中；壳层父级左右 padding 为 0
never: 把页面左右 padding 加在同时包含内容卡片和贴边底栏的父级上；让锁定操作条、键盘或长按条比画布窄一圈并露出两侧背景/蒙层；把内容卡片拉满贴边来迁就底栏
```

### `system-ime-keyboard`

```text
patternId: system-ime-keyboard
when: 业务屏需要表示系统输入法已经升起（对话打字、锁定编辑、表单或搜索聚焦）
stay: 使用规范源「输入框 Agent Input」页上、【用途】为系统输入法整块示意的已发布主组件，贴当前设备画布底边并横向铺满；输入框或锁定操作条坐在键盘上沿。先按该页已发布根组件名搜索，再用 description 门禁确认不是图标、也不是外部系统库
never: 手绘键帽或灰块；用键盘图标或输入框内部 Keyboard 图标代替整块键盘；用 iOS、visionOS、TDesign 等外部库键盘；把键盘缩进内容柱或加页面左右 padding；未发布时当成 gap 自建
```


### `form-validation-timing`

**规则来源**：用户明确的表单产品约束；不是等待现场规范证明的 heuristic。适用于反馈、资料、申请、选择、上传及协议勾选等信息收集场景，生成、迭代和评审均适用。用户明确指定不同校验策略时按本次要求执行并记录。

```text
patternId: form-validation-timing
when: 页面或浮层需要用户填写、选择或补齐信息后提交/下一步/保存
stay: 未满足提交条件时主操作置灰且不可触发；尚未完成不等于发生错误
never: 用初始红字提醒必填；为了展示校验覆盖把错误塞进默认稿；点击禁用按钮后报错；在组件下方生成会顶开布局的错误文案
```

| 状态/触发 | 主操作 | 反馈 |
|---|---|---|
| 首次进入，必填为空、未选类型、未上传或未勾选 | 置灰禁用 | 默认外观；无报错、无 Toast |
| 正在填写、部分完成、未达明确最少字数 | 置灰禁用 | 可用中性格式说明、字数计数或要求；无“描述不足”等红字 |
| 聚焦后失焦仍为空，或已填内容被清空 | 置灰禁用 | 回到未完成态；不因 touched/blur 显示必填错误，也不弹 Toast |
| 已填非空值，结束编辑后确实违反明确格式/范围规则 | 置灰禁用 | 组件下方不生成错误文案；错误走 Toast，点名字段和改法 |
| 所有明确提交条件满足 | 可用 | 清除已提示的错误，不残留红字 |
| 实际提交后服务端拒绝或请求失败 | 按恢复动作确定 | Toast 说明原因与重试动作；保留输入，不把网络错误归咎于字段 |

**错误提示渠道**：只走不改变布局的 Toast；组件下方或字段之间不插入任何错误文案。

| 情况 | 提示 |
|---|---|
| 未填、未选、未达要求 | 无提示，只置灰禁用 |
| 字段格式/范围不符合明确规则 | Toast 点名该字段和改法；不做行内红字 |
| 多个字段同时不符合 | 一条 Toast 列出各字段；同样不做行内红字 |
| 提交失败、服务端拒绝、网络异常 | Toast 说明原因和下一步 |
| 失败后需要重试 | 重试入口放在 Toast 内或按钮本身，不新增占位提示行 |
| 服务端判定与某字段相关（邮箱已注册、内容不合规） | Toast 点名该字段；如需强调，只用不改变尺寸和间距的高亮 |

- **禁止布局位移**：错误提示不得作为文档流元素插在组件下方或字段之间，不使用预留错误占位空间，也不靠撑高行高容纳错误文案。默认稿与错误稿的几何保持一致；需要独立呈现时放浮层或另开画板。
- Toast 文案点名具体字段和下一步，避免只有“提交失败”“输入有误”这类无法定位的句子；提示能被读屏播报。
- 提交条件只能来自需求或确认的业务规则；不得自行增加最少字数、“描述足够具体”等主观门槛。必填文字仅空白字符视为未完成。
- 必填标记、占位和中性辅助说明可解释要求，例如“请选择反馈类型”“至少填写 10 个字”（仅需求确有此限制时）；不要把命令式红字当默认辅助说明。组件下方不保留空的错误占位、错误边框或多余警告装饰。
- 每个错误态在已有状态矩阵中写明具体触发事件、受影响字段和恢复路径；没有触发依据就不生成该错误。错误示例用独立画板/状态呈现，默认稿展示未填写或正常填写态。复用 Template 或库组件时检查并关闭遗留 Error 状态和示例警告，使用合法公开属性，不破坏实例。
- Demo 将提交可用性与错误可见性分开计算，禁止用 `!canSubmit` 直接控制全部报错；禁用操作须拦截点击、回车和表单提交事件，不发请求、不弹提示。这只约束禁用态，提交失败的 Toast 仍按真实结果单独触发。不要只做视觉置灰。
- 截图验收覆盖初始、部分填写、清空、有效填写；需求存在真实错误时再检查对应触发、渠道选择及修正。Figma 与 Demo 同一状态的按钮和反馈保持一致。
