# 对话与生成式回答域

只在 PRD 包含对话、流式生成或结构化回答时读取。本文件定义内容状态，不定义任何 Figma 组件、Variant、Slot、key、颜色或间距配方。

## 思考中（`Thinking`）

- 表达尚未完成；
- 可以追加过程、工具结果和增量内容；
- 不提前出现完成态操作；
- 失败时保留上下文和恢复入口。

## 已完成（`Completed`）

- 保留用户输入与必要过程结果；
- 内容按语义分块并形成清楚层级；
- 建议操作位于内容之后；
- 回复级操作最后收尾；
- 不保留误导性的进行中状态。

## 错误与重试（`Error / Retry`）

- 保留已完成内容和失败位置；
- 失败块留在回答结构里，提供重试、补充输入或退出；
- 不要把已生成正文换成整页空态；
- 重试复用当前上下文，不复制历史回答。

## 内容模型

```text
message:
  role:
  state:
  blocks:
    semanticRole:
    content:
    children:
    interaction:
```

先根据 PRD 和内容语义生成 blocks，再把每个 block 作为抽象槽位走现场组件解析。不得从本文件直接推断组件类型。

## 组合原则

- 标题、正文、列表、数据、代码、媒体、引用、过程和操作按内容语义排序。
- 不用通用容器掩盖原本清楚的内容结构。所有块与组合宿主遵守 [设计规范](design-guidelines.md) 的全局布局、对齐和视觉职责判断；本域不另设组件配色规则。
- 复杂块优先使用现场组件提供的结构能力。
- 内容级操作与回复级操作分层，避免重复。
- 流式更新只改变当前进行中的块，不重建已稳定内容。
- 打字或编辑拉起的系统键盘是设备底边壳层，不是回答内容块。命中 `system-ime-keyboard`：用正式系统输入法示意件贴底铺满，不要画进消息流。

## 现场解析

搜索对话/输出类资产后，完整读取其 description、公开属性和子槽位；具体 block、顺序、间距、内部示意层和状态组合全部以现场为准。内部间距示意层按 description 处理填充后才能交付，不能为对齐库默认 fills 而保留示意色。

## 验收

- 状态与用户感知一致；
- 失败可恢复，完成态无进行中残留；
- 内容层级、顺序和操作位置清楚；
- 内容脚本、Figma 文案与 Demo 渲染逐项一致；流式容器没有裁掉头像、操作或浮层；
- 每个实现 block 都有 Slot Evidence；
- 没有把一次组件实现细节写回本域规则。
