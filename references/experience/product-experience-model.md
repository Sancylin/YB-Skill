# 产品体验模型

本文件定义“元宝这个产品是什么、用户在其中如何行动”的结构，不保存具体组件配方。它为体验决策提供产品事实，不直接规定页面长相。

## 1. 产品事实层级

只允许把以下来源升级为产品事实：

1. 当前 PRD / 用户明确说明；
2. 当前可验证的现网产品行为；
3. 团队明确维护的产品规则；
4. `verified` 体验案例中重复成立且未被当前事实推翻的规则。

AI 自己推导的规律只能是 hypothesis，不得升级为 team rule。

## 2. 建模对象

按任务增量维护，不要求一次补齐全产品：

```yaml
productModel:
  entities:
    - id: "..."
      meaning: "..."
      lifecycle: []
  actors:
    - role: "..."
      permissions: []
  spaces:
    - id: "..."
      purpose: "..."
      typicalTasks: []
  relationships: []
  globalRules: []
  continuityRules: []
  terminology: []
```

重点记录：

- 核心实体与层级；
- 用户角色与权限；
- 信息/功能通常属于哪个产品空间；
- 创建、编辑、删除、分享、生成、发布等生命周期规则；
- 跨页面返回、草稿、历史、选择状态等连续性规则；
- 产品内已有稳定术语。

## 3. 产品规则与体验规则分离

例如：

- “只有管理员可以删除”是产品规则；
- “高风险不可逆操作应提供明确确认与结果反馈”是体验规则；
- “删除入口放在某个具体 Menu 第三项”是 UI/实现决定。

三者不可混写。体验决策可以组合前两类推导方案，但具体 UI 在 UX/UI Freeze 后决定。

## 4. 现网证据的使用边界

体验决策阶段允许查看现网以确认：

- 产品对象、术语、入口关系、权限、已有任务连续性；
- 同类功能已被验证的交互原则。

不允许仅因“现网页就是这样”直接复制布局。若当前任务与现网同类模式高度一致，仍需说明为什么该模式适用；若任务目标或约束不同，可以偏离，并记录差异。

## 5. 冲突处理

当前 PRD > 当前现网事实 > 已认证团队规则 > verified case > 通用启发式。出现冲突时记录 conflict，不静默选择。若冲突会改变业务结果，按 intake 规则澄清；只改变可逆体验方案时由 Experience Reviewer 审定。
