# 真实缺口与可复用组件

仅 [现场组件解析](live-component-resolution.md) 已证明 gap 时创建缺失能力。

## 创建前

保存职责树、`reuseLadder`（前两级均 exhausted）、完整 `libraryCatalog` 与搜索范围证据、相关候选排除理由、结构化 `composeTrials`（试过哪些正式件组合、各缺什么）、可复用子槽位。只做布局的宿主改记 `compose`，不建本地组件。搜索正式库及本任务/目标业务文件的 localComponents 登记表；旧本地件重新验证缺口是否仍成立，不当正式规范。

## 产物类型

- 纯页面布局用 auto-layout Frame；一次性文案/图片用合规内容节点，二者不必伪造为缺口组件。
- 有稳定职责、属性、状态或复用价值的 gap 建为真正的 Figma Component，必要时 Component Set；业务页面用 Instance。
- 正式资产优先；只创建最小缺失部分。内部正式按钮、输入、图标保持真实 Instance，不 detach、不重绘外壳。

## 创建与登记

只在业务文件创建，不写发布库。自建部分从 [基础规范](foundations/index.md) 现场读取变量/样式/模式；按 [设计规范](design-guidelines.md) 递归确定宿主方向、双轴对齐、分布、尺寸和视觉职责；layout 自带合法 padding/gap，禁止复制数值配方。

登记 id / slotId / nodeId / dependencyKeys / instanceNodeIds / evidenceRefs。新建前比较语义、宿主、状态、内容边界，不仅按名称或外观查重。同一能力多页面复用一个适当主组件；不得复制 Frame 冒充复用。

公开属性服务业务语义，最少且足够；只覆盖需求需要的状态，不制造展示用变体矩阵。description 说明用途、适用场景、使用规则、属性/状态、规范细节、禁用方式，以及正式子组件依赖和内容增长策略。

## 验证与反查

验证必要状态、短/典型/长内容、目标尺寸与主题、属性变化范围、基础绑定和正式子件来源。修复主组件时检查所有已登记实例的影响。

最终从交付节点反查：每个自建交互结构是正式资产或已登记 gap；每个本地主组件有登记；所有 instanceNodeIds 回指正确主组件；layout/content 分类有实际角色依据，不能靠标签藏自绘按钮。系统审计扫描范围内全部相关节点，包括未登记自建，而不只读登记表。

临时节点清零，保留正式复用部分与风险。可建议设计系统收录；发布或修改规范源不属于本任务默认授权。
