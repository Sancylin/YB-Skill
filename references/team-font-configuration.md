# 云端字体配置与文案写入

## 默认链路

先验证实际 MCP 账号在目标文件中能否加载所需字体，能加载则直接使用，不因团队列表为空重复上传。确实缺失时优先团队/组织共享；团队未配置或当前用户没有团队上传权限时，自动走**当前账号上传字体**。已有团队字体仍加载失败时，先核对账号、文件作用域和精确字体名称；确认账号上传可补齐后才上传缺失项。

字体配置是可复用的初始化，不是每个 PRD 都要重做。个人上传只解决当前账号，不能宣称已配置全团队。工作流不依赖本机改字插件、桥接服务或电脑代改文案；电脑操作仅用于官方上传界面。

## 准备与上传

1. 首次团队配置只读扫描规范库文字样式及各页 TEXT 的全部字符段，统计精确 family/style，并区分正式组件依赖、样例与历史素材。具体任务只补齐当次选中组件及其变体/子组件所需字体，不上传整库历史样例字体。变量驱动的字体覆盖有关模式，不能忽略混合字体；库更新后核对受影响依赖。
2. 在目标业务文件对应的 MCP 账号中枚举字体并测试精确加载，已可用项无需上传。
3. 对缺失项优先按下节从随包 assets/fonts 定位文件，通过清单、校验值及字体内部名称匹配 family/style，不能根据文件名或近似名称冒认。DINPro 与 DIN Pro 的兼容性需精确加载实测，不改字体内部名称或 token 来适配。
4. Figma 团队/组织字体上传需相应管理员权限，接受 TTF、OTF。使用已获平台上传授权的原字体资源；遇到 TTC 格式先确认许可与兼容性，不改后缀假装格式转换，随包字体使用已获内部共享及平台上传授权的资源，不改字体内部名称、字形或 token。
5. 有电脑操作能力且当前任务授权覆盖上传时，由 AI 操作官方字体管理界面，核对登录账号与 MCP 账号一致、字体族与字重后上传缺失文件。已有授权不重复询问；平台要求的权利声明不能由 AI 猜测，确需用户确认时只交接该步骤。已有同名字体先核实版本，不能直接覆盖团队资源。

## 随包字体定位

以本次实际加载的 `SKILL.md` 所在目录为 Skill 根目录，解析 [字体清单](../assets/fonts/manifest.json) 中的文件名到该根目录的 `assets/fonts/`；不能以产品项目的当前工作目录为根，也不能写死作者机器或某种客户端的安装路径。压缩包需先解包或安装，保留此相对结构；若宿主只提供文档内容、无法访问附带文件，则交接用户从原包解压字体。

包内包含 PingFang SC 的 Regular、Medium、Semibold 和 DIN Pro 的 Medium。它们是缺字时的候选资源，不是组件库字体需求的固定上限；不覆盖未打包字体（例如 YB Serif UI）。始终以本次组件依赖为准，仅上传缺失项。

读取清单并校验文件大小及 SHA-256；可运行 Skill 根目录下 `scripts/validate-skill.py` 检查包完整性。字体二进制只用于校验和上传，不输出 Base64、不读入模型上下文。校验失败或缺少所需字重时，说明具体文件缺项，要求重新获取完整包或匹配原件，不凭近似字体继续。

AI 可操作电脑时，在已授权范围内将找到的文件上传至对应 Figma 团队/组织或当前账号。不能操作时，给用户解析后的绝对文件路径及下节上传步骤；用户在另一台电脑操作时同时给出包内相对路径。仅下载或安装到电脑不代表 MCP 可用，上传后仍须完成写入验收。随包存在不等于已获得任何成员的自动上传授权。

## 当前账号上传与人工交接

账号上传入口（不是团队设置）：Figma 文件首页 → 左上角头像 → **Settings → Account → Your uploaded fonts → Upload fonts**。选择匹配的 TTF/OTF，按界面要求确认拥有上传权利和允许 Figma 存储使用，完成后查看 Uploaded fonts 列表；字体选择器中可显示为 Uploaded by you。

没有电脑操作工具、工具无法操作上传控件或必须由用户确认权利时，直接给用户以下具体交接，不要求其手改设计稿：

> 当前缺少：[本次所需 family/style 清单]。请登录与 MCP 相同的 Figma 账号 [已核实账号；未知时说明需核对]，打开文件首页左上角头像 → Settings → Account → Your uploaded fonts → Upload fonts，选择 [已找到的文件绝对路径；未找到则列出需提供的原件]。完成界面要求的字体权利确认并上传。看到字体出现在 Uploaded fonts 后，回复“已上传”；我会重新检查 MCP 字体加载，通过后从 [当前阶段/目标] 继续任务，保留原 token。

入口不存在或被组织策略禁用时，说明实际界面限制并给出团队管理员恢复路径，不指导绕过组织限制。只有 TTC、缺原件或缺上传权利时说明具体缺项；安装本机字体不等于账号上传成功。

交接前在当前运行记录保存缺失字体、账号/文件作用域、目标节点、阶段、证据和下一步。受影响写入暂停，独立工作可继续；用户回复已上传后按下节重新验证，不重建已有页面，不把回复本身当作能力通过。

## MCP 写入验收

团队或个人面板显示上传成功并不等于 MCP 可用。记录字体来源为 team/organization/account，以及核实的 MCP 账号、fileKey、family/style；在实际目标文件中重新执行 `listAvailableFontsAsync` 和 `loadFontAsync`。正式写入前读目标真实字体段并加载全部字体，只修改合法公开内容属性或允许的内容覆盖。

最小写入 probe 需保留字体名称、文字样式 ID、字体/字号/字重/行高/颜色变量绑定以及实例主来源，写后读回并检查截图。混合格式按字符段映射处理，字符串变量内容按合法内容属性处理，禁止整段覆盖破坏格式。测试完成恢复原文或清理当次临时节点。

团队无权限先走账号上传；账号路径也不可行、文件缺失、许可未确认或 MCP 加载仍失败时记录真实 blocker 和恢复入口。受影响内容不能完成，不换字体、不解绑 token、不安装改字插件。能力证据仍按 [能力预检](capability-preflight.md) 和 [运行记录格式](run-record-format.md) 注册；写入按 [组件实例安全](component-instance-safety.md)，账号上传不得放宽原有门禁。

官方说明：[团队/组织字体](https://help.figma.com/hc/en-us/articles/360039956774-Upload-custom-fonts-to-an-organization)、[账号上传与 MCP 字体](https://help.figma.com/hc/en-us/articles/360039956894-Add-a-font-to-Figma)。组织共享与个人上传作用域不同，必须以当次 MCP 实测为准。
