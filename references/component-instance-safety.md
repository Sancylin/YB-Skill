# 正式实例写入安全

本文件只规定写入事务，不保存任何组件的属性配方。

## 1. 创建来源

- 组件 key 必须来自当次现场组件解析。
- import 后新建 Instance；禁止 clone 业务实例、detach 或修改正式库主组件。
- 写入前记录组件 key、父级、公开属性定义、默认尺寸和当前 override。

## 2. 允许写入

按优先级：

1. 通过实例公开属性设置 Variant、Boolean、Text、Slot 或 Instance Swap。
2. 按父组件 description 解析并填充子槽位。
3. 仅在配置允许的业务案例范围内，对已记录文本节点做最小内容覆盖。同一行已有业务 subtitle / trailing 时，隐藏仍露出的默认示意文案（如「描述文本」），只留进入控件；这是内容覆盖，不是改内部布局。切换公开属性后读回实际可见插画和占位，不能假设变体名等于插画已替换。
4. 设置实例的语义名称、父级位置和经 Screen Spec 允许的外层布局。
5. 现场 description 写明实例化后必须处理的内部间距示意填充：只改该示意层填充可见性（隐藏或透明度归零），保留几何与层级，不删层。这是交付必做，不能为了让保护字段等于库默认而把示意色留在可见态。

Slot 是结构槽，不是字符串；写入内容必须符合该槽位的现场类型和组合规则。

## 3. 字体能力门禁

任何可能改变文本内容的操作前：

1. 读取目标文本实际使用的全部 `family + style`；
2. 用 `listAvailableFontsAsync()` 精确检查；
3. 全部可用后逐个 `loadFontAsync()`；
4. 任一不可用则暂停当前通道，按 [团队字体配置](team-font-configuration.md) 依次检查团队与账号字体配置；原字体未被 MCP 加载前记录 degraded，配置完成后重新验证。

在 `use_figma` 提供 Figma Plugin API 时执行上述检查。当前工具若无法枚举或加载字体，记录缺失能力并按云端字体配置恢复；不得猜测已加载。本机编辑器能显示不代表插件环境能加载。禁止换字体规避；随包字体按云端字体配置校验并上传，不能仅凭文件存在判定 MCP 可用。字体导致迁入布局宿主失败时按 [设计规范](design-guidelines.md) 的布局宿主规则处理，不以编组规避。degraded 文本保留正式实例默认内容，评审时单列未解决项及已尝试的自动恢复路径，不把缺真实文案记成已完成。

## 4. 快照

写入前后核对身份和可见结果：

- main component key、公开属性和 override；
- font、text style、variables、fills、effects；
- 尺寸、布局约束和父级关系；
- 本次允许的可见变化（名称、外层布局、公开属性、内容、示意填充）。

名称、布局、公开属性和内容不必为每个 JSON 路径补白名单。白名单只是抽查日志，缺路径不能否掉正确稿。根路径 `/` 仍禁止。换字体、解绑变量、detach、改非示意层填色仍是非法变化。

## 5. 事务

1. 保存槽位证据（`Slot Evidence`）和目标节点 ID。
2. 生成 preSnapshot；需要抽查时再写 write whitelist。
3. 先写公开属性和子槽位，再写允许的业务内容与 description 要求的示意填充处理，最后写外层布局。示意填充变化记入 `descriptionFillAdjustments`，摘录必须能对上组件 description。
4. 生成 postSnapshot 并比较身份字段。
5. 成功则写入实现日志（`Implementation Log`）；能力受限则 degraded。
6. 身份被破坏（detach、换字体、解绑变量、改非示意层填色）才记 `illegal-mutation`：本轮新节点可删除重建；既有节点按 preSnapshot 精确恢复本次变化，无法证明恢复则停止并报告，不能删用户已有实例。缺白名单路径不是 illegal-mutation。

不得对用户已有实例执行全量 reset，也不得深入后代“补救”非法写入。

## 6. 禁止

- 修改规范源、正式库主组件或发布库默认内容；
- 修改正式实例后代视觉、字体、变量或内部布局。唯一例外：现场 description 要求处理的间距示意填充，且只改填充可见性；
- 用示意填充例外去换字体、解绑变量、改非示意层填色、改内部布局或 detach；
- 页面级按名字批量写节点；
- 用本地缓存 key 直接实例化；
- 用遮罩、外挂内容或自建副本伪装组件能力。

## 7. 审计

每个实例必须能回溯到 Slot Evidence、所用组件 key、最终 nodeId 和可见截图。状态处理见 [state-and-fallback.md](state-and-fallback.md)。
